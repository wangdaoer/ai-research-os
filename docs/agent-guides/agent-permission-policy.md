# Agent 权限分级与执行记录

> 目标：让 Agent 能够提高效率，同时不越过资料、资金、对外沟通和发布边界。  
> 适用范围：本仓库中的研究、数据整理、Agent 工作流和自动化任务。  
> 最后更新：2026-10-19

## 1. 基本原则

- 最小权限：只授予完成当前任务所需的最低权限。
- 默认可读、受控可写、关键动作必确认。
- 每一项重要写入都应可追溯、可说明、可回退。
- 不以“提高效率”为理由绕过人工审批。

## 2. 权限等级

| 等级 | 行为 | 是否可自动执行 | 必须保留的证据 |
| --- | --- | --- | --- |
| P0：规划 | 拆解任务、提出方案、生成草稿 | 是 | 任务目标与假设 |
| P1：只读研究 | 读取公开资料、仓库文件、已授权的数据源 | 是 | 来源链接、读取范围、日期 |
| P2：受控写入 | 新建/修改 Markdown、JSON、模板、研究记录；在代码库中提交可逆变更 | 是，但必须记录 | 文件路径、变更摘要、验证结果、提交信息 |
| P3：人工确认后执行 | 对外发送邮件/消息、发布内容、修改云端权限、创建付费资源、部署生产环境 | 否 | 用户明确确认、目标、最终内容或变更范围 |
| P4：禁止自动执行 | 删除重要资料、真实买卖投资产品、转账/付款、共享敏感信息、保存密钥 | 否 | 仅允许用户亲自完成或逐项明确授权 |

## 3. 常见动作判定

| 动作 | 权限 | 说明 |
| --- | --- | --- |
| 整理 AI 周报、行业资料、研究卡 | P1 | 必须引用原始或可信来源 |
| 在 `research/` 新建可回退的研究记录 | P2 | 文件名需包含日期或主题 |
| 修改模板、提示词、工作流规则 | P2 | 需要说明影响范围 |
| 导入本地自选股的脱敏 JSON/CSV | P2 | 先校验格式，异常数据不得覆盖旧数据 |
| 向 X、微信、邮箱、Slack 发布或发送内容 | P3 | 先展示最终版本，等待确认 |
| 配置 API Key、OAuth 授权或支付方式 | P3 | 仅在用户明确提出时操作，不记录敏感值 |
| 下单、交易、付款、删除仓库或云端文件 | P4 | 不由 Agent 自动执行 |

## 4. 必经审批点

以下情况即使任务流中允许自动运行，也必须暂停并请求确认：

1. 目标从内部资料变为外部传播。
2. 将读取权限升级为写入、发送或支付权限。
3. 影响范围从测试文件扩大到正式资料、生产系统或真实客户。
4. 发现来源冲突、数据缺失、疑似敏感信息或重大风险。
5. 需要覆盖、删除或不可逆修改既有内容。

## 5. 执行记录模板

每个 P2 及以上的任务，在提交说明、运行日志或交付结果中至少记录：

```markdown
- 任务：
- 目标：
- 输入与来源：
- 执行范围：
- 变更文件/对象：
- 验证方式与结果：
- 未解决事项：
- 权限等级：P0 / P1 / P2 / P3 / P4
- 是否需要人工确认：是 / 否
```

## 6. 失败与异常处理

- 读取失败：说明缺失的来源、权限或文件，不编造结果。
- 数据异常：隔离异常输入；不得破坏已有数据。
- 运行失败：保留错误摘要、已完成步骤和可安全重试方式。
- Agent 输出不确定：标记为“待核实”，不写入正式结论。
- 可疑工具调用：停止执行，保留最小必要信息并请求人工判断。

## 7. 首轮落地清单

- [ ] 所有研究自动化任务按 P1 执行，输出必须含来源。
- [ ] 所有仓库写入按 P2 留下提交或变更摘要。
- [ ] X 内容、邮件、微信消息默认设为 P3。
- [ ] 投资动作、支付、删除统一设为 P4。
- [ ] 每个新 Agent 工作流附上输入、输出、审批点和失败处理说明。
